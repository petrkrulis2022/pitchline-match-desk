# Pitchline Match Desk

Explainable AI match coverage from messy match data, built for the Microsoft "Inside the Game" hackathon.

Football data arrives late and incomplete: events are stamped a few seconds after they happen, a card can show up minutes late, and a vision feed misses players and rarely finds the ball. Match Desk reconciles those feeds into a verified record, then a team of AI agents on Microsoft Foundry writes a live blog and a match report in English, Spanish and Czech. Every number, score, minute and name has to trace back to the record, and a Verifier agent checks the claims.

**All data is synthetic.** The clubs, players, referee and every event are invented, generated by `synth/engine.py` from a seed. No real match data, footage or broadcast material is used anywhere in this repository.

## What is in the demo

- A 90-minute match between two fictional clubs, Redmoor Athletic and Stonebridge Town (a 2-1 win after a VAR-cancelled goal).
- A live blog of about 65 entries, one every minute and a half on average, that can be replayed at 90 times speed with the score and clock following the match.
- A match report of about 750 words in seven sections, with a shot map, a possession chart by 15-minute spell, top-performer tables, statistics and line-ups.
- English by default, with Spanish and Czech switches for both.
- A "How it was made" view showing what each stage did on this run.

Open `web/index.html` in a browser, or host the `web/` folder on any static host.

## How it works

1. **Match engine** (`synth/engine.py`): 22 players and the ball simulated 10 times a second, with exact ground-truth events. Standard library only.
2. **Noisy feeds** (`synth/feeds.py`): from the truth it builds an events feed (stamped late, occasional cards delivered minutes late) and a vision feed (players found about nine times in ten, a ball that is often missing or wrong, close-ups and replays that hide the pitch).
3. **Reconciler** (`synth/facts_builder.py`, `synth/enrich.py`): turns about 2,200 raw events into roughly 150 weighted moments. It matches late-stamped cards back to the foul that caused them, applies VAR decisions to the score, cross-checks shots and goals against the vision feed, and derives line-ups, corners, fouls, defensive stands, pressing wins, passing sequences, spells of pressure, 15-minute windows (possession and field tilt) and per-player statistics.
4. **Agents** (`pipeline/`): built with Microsoft Agent Framework (`Agent` plus the OpenAI-compatible chat client) on a Microsoft Foundry deployment.
   - Commentator: writes live-blog entries from the verified moments.
   - Fixer: repairs entries that fail a check.
   - Analyst: writes half-time and full-time insights from the statistics.
   - Editor: writes the match report.
   - Verifier: reads each claim against the record and flags anything contradicted or invented.
   - Localizer: translates entries and the report into Spanish and Czech.
5. **Fact-check gate** (`pipeline/check.py`): deterministic. Every number, score, minute and name in an agent's output must trace to the facts, no quotes may be invented, and translations must keep names and numbers. Output that fails goes back to the Fixer; if it still fails, a plain template is used instead.
6. **Site** (`site/build_synth_site.py`): one self-contained page.

## Microsoft stack

- Microsoft Foundry: model deployment (DeepSeek-V4-Flash, Global Standard) reached through the OpenAI-compatible endpoint.
- Microsoft Agent Framework: the agents.
- The page is static and can be hosted on Azure Static Web Apps.

## Run it

Python 3.10 or newer.

```
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # fill in your Foundry endpoint, key and deployment name

python synth/feeds.py 6                         # engine + feeds (standard library only)
python synth/facts_builder.py synth/out/match-006
python pipeline/run_pipeline.py                 # agents; needs the .env values
python site/build_synth_site.py synth/out/match-006
```

The generated data for seed 6 is committed under `synth/out/match-006/`, so the site can be rebuilt without calling the model. Regenerating the engine and feeds from the seed reproduces those files exactly.

## What the checks do and do not do

- The deterministic gate catches wrong numbers, scores, minutes and names, invented quotes, and translations that change names or numbers.
- It cannot judge meaning. The Verifier agent covers that, and it is itself a model: it can miss a mistake and it sometimes flags a correct sentence.
- Model output varies from run to run. `synth/out/match-006/pipeline_log.json` records what the agents did on the committed run, including repairs.
- The noise levels in the feeds are illustrative, not measurements of any data provider.
- Agents are orchestrated with plain `asyncio` around Agent Framework agents, not with its workflow builders.
